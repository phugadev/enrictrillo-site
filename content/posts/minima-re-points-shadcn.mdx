## One file, the same class names

{/*
  The claim that makes Minima different from "a shadcn theme":
  - It ships as one CSS file. Existing shadcn components pick it up without
    being edited, because it re-points Tailwind's own shadow, easing and
    colour scales rather than inventing a parallel set of names.
  - Radius is the one scale shadcn keeps; install needs a one-time edit to
    hand it over (docs/install.md). Say so — it's the honest caveat.
  - The README's stock-vs-Minima screenshots are the same markup both ways.
    Worth an image here (docs/images/dashboard-stock.png / -minima.png).
*/}

```bash
npx shadcn@latest add phugadev/minima/theme
```

```css title="app/globals.css"
@import "tailwindcss";
@import "../styles/minima.css";
```

## The decisions shadcn leaves to you

{/*
  Pick two or three from the README's "A few of the decisions". Strongest,
  because each has a concrete failure behind it:
  - Ask for a role, never a step number. Renumbering the scale once left four
    files quietly wrong; a name survives that.
  - Text goes on a fill, never a tint. Seven hue/ground pairs land 4.20–4.48:1
    on other grounds — under the floor, but only just.
  - Each mode runs out of room at the opposite end: light spends its range on
    shadow, dark on surface.
  - The type scale is type-*, not text-*: cn() files a custom text-body as a
    colour and silently drops it. (A good <Compare> candidate.)
*/}

## The first consumer is this site

{/*

  - 1.1.0: Shiki follows the page's mode (before, every consumer wrote the

  - 1.2.0: minima-palette.json, replacing three hand-rolled colour resolvers

    site's redesign hand-rolled one.
  And what building on it still turned up (28 Sep 2026), all currently fixed

  - prose body in dark mode used a reading grey (0.88) nearly as bright as
    headings (0.96);
  - Minima's highlighted-line margin shifted highlighted code lines left;
  - Minima's Shiki rule applied colour but dropped the themes' italics.
